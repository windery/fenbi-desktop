# 设置菜单：显示版本号与检查更新

状态：未开工（第 1 块待做）

## 要解决什么

用户在软件里看不到自己装的是哪一版，也不知道有没有新版、去哪里下载。Windows 没有菜单栏，问题最明显。

做成后：用户点工具栏上的齿轮，能看到当前版本号；有新版时齿轮带红点，菜单里能去发布页下载。

## 已定的决定

| 事项 | 决定 |
| --- | --- |
| 入口 | 工具栏只加一个齿轮按钮；版本号不放窗口标题栏 |
| 设置界面 | 点齿轮弹出系统原生菜单 |
| 版本号 | 菜单第一行，取自 `tauri.conf.json` |
| 自动检查 | 每次启动查一次，运行中不再查 |
| 版本来源 | 本仓库的 GitHub 发布页（最新发布） |
| 新版提醒 | 只有红点，不出文字、不弹窗；红点留到本机版本不低于最新版本 |
| 工具栏收起时 | 不显示齿轮；有新版时细条的「展开」把手带红点 |
| 下载 | 用系统浏览器打开 GitHub 发布页，软件不经手安装包 |
| 本地记录 | 不存任何提醒记录 |

细节：

- 菜单文字：「版本 v<当前版本>」（灰色，不可点）、「检查更新」、「下载新版 v<最新版本>」（有新版才出现）。
- 手动点「检查更新」的结果显示在工具栏提示区：「已是最新版本」「发现新版本 v<最新版本>」「检查更新失败，请稍后再试」。
- 自动检查失败不出任何提示。
- 齿轮在三个平台都显示，位置在工具栏右侧、收起按钮的左边。
- 工具栏是独立的 36 高 WebView，网页下拉面板画不出这个高度，所以用原生菜单（Tauri 的 `Menu::popup`）。

## 分块

每块开工前先出方案，批准后再动手；先写测试再写实现；改完跑 `pnpm check`。

- [ ] **第 1 块：齿轮、原生菜单、版本号**（不联网）
  - `src-tauri/toolbar/toolbar.js`、`toolbar.css`：展开状态加齿轮图标按钮，悬停提示「设置」。
  - `src-tauri/src/toolbar.rs`：新增只允许工具栏调用的命令，弹出原生菜单，菜单只有版本一行。
  - `src-tauri/capabilities/toolbar.json` 和命令权限声明：给工具栏加这一个命令的权限。
  - `tests/js/toolbar.test.mjs`：断言展开时有齿轮、收起时没有、点击只向 Rust 发这一个命令。
  - `CLAUDE.md` 描述工具栏的那句补上「设置菜单」。
  - 验收：`pnpm dev` 里齿轮能弹出菜单，版本号正确。Windows 上菜单的样子在虚拟机里另看。
- [ ] **第 2 块：检查更新、红点、下载入口**（联网）
  - 启动时检查一次；菜单加「检查更新」「下载新版」；齿轮和收起细条的红点。
  - 给包装层加「只允许打开发布页这一个固定网址」的能力。
  - `CLAUDE.md`「包装层的边界」一段补上检查更新这件事；记一条 ADR（包装层自己联网检查更新的理由）。

## 不在范围内

- 自动下载、自动安装。
- 粉笔页面、注入脚本 `init.js`、登录逻辑。
