# 设置页面：显示版本号与检查更新

状态：已完成（「没验证的」几项不验了，有问题再说）

## 要解决什么

用户在软件里看不到自己装的是哪一版，也不知道有没有新版、去哪里下载。Windows 没有菜单栏，问题最明显。

做成后：用户点工具栏上的齿轮，进入设置页面，能看到当前版本号；有新版时齿轮带红点，设置页面里能去发布页下载。

总的口味：克制，尽量不影响正在做题的人。

## 已定的决定

| 事项 | 决定 |
| --- | --- |
| 入口 | 工具栏只加一个齿轮按钮；版本号不放窗口标题栏 |
| 设置界面 | 点齿轮，主窗口里粉笔页面那一块换成设置页面；工具栏留着；粉笔页面在后面保持原样，不刷新、不跳转 |
| 设置项 | 第一版只有「版本与更新」一组；以后有新设置再加组 |
| 版式 | 浅灰底上一张白卡片；规范见 `DESIGN.md` |
| 版本号 | 设置页面「版本与更新」一组里，取自 `tauri.conf.json` |
| 自动检查 | 每次启动查一次，运行中不再查 |
| 版本来源 | 本仓库的 GitHub 发布页（最新发布） |
| 新版提醒 | 只有齿轮上的红点，不出文字、不弹窗；用户打开设置页面后红点消失，出了更新的版本再亮 |
| 工具栏收起时 | 不显示齿轮；展开把手不带红点 |
| 下载 | 用系统浏览器打开 GitHub 发布页，软件不经手安装包 |
| 本地记录 | 只存一个「已看过的版本号」，和工具栏展开/收起状态同一目录 |

细节：

- 设置页面第一版只有「版本与更新」一组，是一张卡片。卡片第一行：应用图标（用 `src-tauri/icons/` 里现有的）、应用名「粉笔刷题」、「当前版本 v<版本>」，右边是「检查更新」按钮。
- 手动检查：按钮文字变成「正在检查更新…」，前面有一个转圈的圆环。查完卡片多出第二行：颜色圆点加一句「已是最新版本」（绿）/「发现新版本 v<版本>」（蓝）/「检查更新失败，请稍后再试」（红）；有新版时这一行右边是「下载新版 v<版本>」按钮。工具栏不出字。自动检查失败不出提示。启动时已经查到新版时，打开设置页面就直接显示「发现新版本」这一行，不用再点「检查更新」。「已是最新版本」和「检查更新失败」关掉设置页面就清掉。
- 回到粉笔页面：页面左上的返回箭头（紧挨「设置」标题，悬停显示「返回」）、再点齿轮、按 Esc。
- 设置页面开着时，工具栏的返回、前进、回题库、刷新、收起都变灰，它们的快捷键不起作用。
- 「下载新版」用系统浏览器打开发布页；网址写死在 Rust 里，界面只发动作、不传网址。
- 齿轮在三个平台都显示，位置在工具栏右侧、收起按钮的左边。齿轮没有快捷键，悬停提示是「设置」。
- 做法：设置页面开着时，工具栏那个本地页面撑满窗口，设置内容画在工具栏下面，粉笔页面大小不变、挪到窗口之外；不新增第三个页面。见 `docs/adr/0002-设置页面由工具栏页面撑满窗口.md`。
- 最新版本号的读法：请求发布页网址，从跳转地址读版本号。请求用 `ureq` 在后台线程发，带超时。

每块开工前先出方案，批准后再动手；先写测试再写实现；改完跑 `pnpm check`；做完给负责人看过再做下一块。

已做：

- [x] **齿轮按钮**（`ec11646`）。同一提交里的系统原生菜单由第 1 块删掉。
- [x] **启动时检查更新、齿轮红点**（`ed955c4`，`src-tauri/src/update.rs`）。同一提交里展开把手上的红点由第 3 块去掉。
- [x] **版式**。定为白卡片分组，规范写在 `DESIGN.md`。
- [x] **第 1 块：设置页面的开和关**。点齿轮进出只有标题行的设置页面；三种返回办法；其它工具栏按钮变灰、快捷键不起作用；系统原生菜单已删。macOS 和 Windows 上实测过：设置页面开着时粉笔页面的计时不变慢、不刷新、大小不变，按键不漏给粉笔页面。
- [x] **第 2 块：「版本与更新」的内容**。卡片显示版本号、「检查更新」和结果一行、「下载新版」；「下载新版」用 `open` 库让系统浏览器打开写死的发布页网址。macOS 上对着本机假发布页实测过三种结果和「启动时已查到新版」，下载按钮打开了默认浏览器。Windows 上实测过卡片的样子、一次真实检查（结果是已是最新版本）、打开发布页（Edge）。

- [x] **第 3 块：红点看过就消失**。已看过的版本号存在应用数据目录的 `seen-version`（一行版本号，只升不降）。三种情况会记下它：打开设置页面；在设置页面里点「检查更新」查到新版；启动时的检查在设置页面已经开着时才查完。红点只在新版高于已看过的版本号时出现。卡片里的「发现新版本」一行和「下载新版」不受影响，看过之后每次打开设置页面仍然显示。展开把手不再带红点。macOS 上对着本机假发布页实测过：打开设置页面后红点消失、卡片仍显示「发现新版本」；重启后同一版不亮；发布页换成更高的版本再亮；启动时就是收起的工具栏，展开把手上没有红点。

## 没验证的

- Linux 上设置页面的开和关：那段代码没有在 Linux 上编译过，也没有实测过。
- 真实考试页的倒计时：只用本机假页面测过计时，没有用真实考试测。
- Windows 和 Linux 上红点看过就消失（只在 macOS 上实测过）。
- macOS 上「红点在打开设置页面的那一刻消失」没有截到图：实测时窗口开在别的桌面空间，页面不重画。这一条是用临时驱动读页面内容确认的，重启前后的样子有截图。
- Linux 上齿轮、红点和卡片的样子；Windows 上红点、「发现新版本」「检查更新失败」「正在检查更新…」的样子（正式版只认真实的 GitHub，测不到这几种）。
- 读屏软件是否播报检查结果。
- 中国大陆直连 GitHub 时检查更新能否成功。
- 安装包因 `ureq` 变大了多少。

## 不在范围内
