# 做题页划词标记放宽注入边界

用户想在做题时给题干划重点（GitHub 议题 #11）。这要包装层往粉笔页面里加一段脚本，监听按键和鼠标位置，超出了原来「包装层只注入 CSS」的边界。负责人决定放宽一次，只放宽到这一处：独立的 `highlight.js`，只在做题页（`spa.fenbi.com` 上的练习和背题，路径正好带一个 id）生效，只用浏览器自带的 CSS Custom Highlight API 给选中的文字叠底色。它不往页面插元素、不改站点的题目节点，不读题目数据（只看选区的位置和文字节点的长度，不取文字），不调站点接口、不联网。第一版不调用 Tauri IPC、不写任何存储，标记刷新或换页就没了；第二版改成按练习落盘，见下文「第二版：按练习落盘、操作改顺手」。

选 CSS Custom Highlight API，是因为它不碰 DOM：高亮是登记在 `CSS.highlights` 里的一组 `Range`，由浏览器画出来，不改站点的题目节点，站点的 Angular 视图和站点脚本里自带的划线库（靠包 `<span>` 工作）都不会被它打乱。登记表和站点在同一个文档里，同页的站点脚本读得到它，只是站点不会去读；这一点不当作隔离。站点把节点换掉时范围随之失效，包装层只需认出失效并清掉，不需要跟着站点的结构走。代价是老 WebView 不支持（Safari 17.2 之前、部分 Linux 的 WebKitGTK），那时功能直接不出现，不报错。

第一版只做「选中按 H 标记、悬停换色或删除、清当前题」，不能改键，也不做按 E 打开站点的编辑。

## 第二版：按练习落盘、操作改顺手（2026-11-28）

用户用过第一版后反馈「选中再按 H、悬停再按删除」太麻烦，并要求标记按一次练习记住、关掉应用再打开还在。2026-11-28 用户授权放开存储边界，**仅限划词标记**；登录态（cookie、`sess`、凭证信号）不落盘的边界原样保留。

- **存哪**：Rust（`marks.rs`）在应用数据目录存一个文件，按练习（`exercise:<id>` / `memorize:<id>`）分条，每条只存「第几道题 + 题内文字偏移 + 颜色 + 最后修改时间」，不存选中的文字；先写临时文件再改名。
- **粉笔页面能做什么**：只多了两条窄命令——按练习读、按练习写（权限 `allow-practice-marks`，只给 main WebView）。写入时 Rust 校验练习 id、每条结构、单个练习和整个文件的大小，超限拒绝。没有列举、删除别的练习的能力；「清除全部标记」只有本地设置页面能调。
- **能关、会过期**：设置里「记住标记」关掉时不读不写文件；「标记保留」默认 30 天（7 / 30 / 90 / 永久），启动时清掉过期的。
- **操作**：拖选松手即标记（设置里可换回「选中后按键标记」）；右键点标记删除、Shift+右键换色；一键显示 / 隐藏、一键换笔色；键位和颜色都能在设置里改。松手标记时吞掉紧跟着的那次 click，免得拖选误选选项（借鉴提议人 fork 的 `suppressClickFor`）。
- 仍然只用 CSS Custom Highlight API，不往页面插元素。

### 第二版没选的做法

- **存在 `sessionStorage`**：关掉应用就没了，满足不了「重启后还在」。
- **存在粉笔站点的 `localStorage`**：设置页面在别的页面时清不到 `spa.fenbi.com` 的存储，站点也可能自己清。
- **交卷后自动清掉这份练习的标记**：要判断站点的答题状态，越过「不判断站点业务」的边界。

## 没选的做法

- **照搬用户 fork 的实现**：负责人看过 fork 编出来的版本后决定不采用。它往站点页面里加了自己的按钮和元素，边界比这里宽得多。
- **用 `<mark>` 之类的元素把选中的文字包起来**：要拆分、改写站点的文字节点。Angular 重新渲染时会和它打架；站点脚本里自带的划线库（`highlight-mengshou`）同样靠包 `<span>` 工作，两边会互相拆。
- **按 E 驱动站点自己的「编辑」**：要包装层去点站点的按钮，属于驱动站点业务，正是边界里要求停下确认的那一类；划词标记已经覆盖了划重点的需求。
- **选中文字就自动上色**（第一版没选，第二版改成默认）：第一版担心选文字复制时也会被标上，所以要多按一次 H；用户反馈多按一次太麻烦，第二版默认松手即标记，常复制的人可以在设置里换回「选中后按键标记」。
