# 做题页划词标记放宽注入边界

用户想在做题时给题干划重点（GitHub 议题 #11）。这要包装层往粉笔页面里加一段脚本，监听按键和鼠标位置，超出了原来「包装层只注入 CSS」的边界。负责人决定放宽一次，只放宽到这一处：独立的 `highlight.js`，只在做题页生效，只用浏览器自带的 CSS Custom Highlight API 给选中的文字叠底色。它不往页面插元素、不改站点节点，不读题目数据（只看选区是否为空和它的位置，不取文字），不调站点接口、不联网，不写任何存储，标记刷新或换页就没了。

选 CSS Custom Highlight API，是因为它不碰 DOM：高亮是登记在 `CSS.highlights` 里的一组 `Range`，由浏览器画出来，站点的 Angular 视图和站点脚本里自带的划线库都看不到它，也不会被它打乱。站点把节点换掉时范围自然失效，包装层不需要跟着站点的结构走。代价是老 WebView 不支持（Safari 17.2 之前、部分 Linux 的 WebKitGTK），那时功能直接不出现，不报错。

第一版只做「选中按 H 标记、悬停换色或删除、清当前题」，不能改键，也不做按 E 打开站点的编辑。

## 没选的做法

- **照搬用户 fork 的实现**：负责人看过 fork 编出来的版本后决定不采用。它往站点页面里加了自己的按钮和元素，边界比这里宽得多。
- **用 `<mark>` 之类的元素把选中的文字包起来**：要拆分、改写站点的文字节点。Angular 重新渲染时会和它打架；站点脚本里自带的划线库（`highlight-mengshou`）同样靠包 `<span>` 工作，两边会互相拆。
- **按 E 驱动站点自己的「编辑」**：要包装层去点站点的按钮，属于驱动站点业务，正是边界里要求停下确认的那一类；划词标记已经覆盖了划重点的需求。
- **选中文字就自动上色**：选文字复制时也会被标上，所以要多按一次 H。
